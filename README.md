# sentgraph-mcp

Go MCP-сервер долговременной памяти для кодинг-агентов на базе Zep Cloud.

Sentgraph держит локальный слой тонким:

- Zep Cloud отвечает за построение графа, дедупликацию, эмбеддинги и извлечение.
- Sentgraph отдаёт агенту шесть базовых MCP-инструментов.
- Нативные Go-хуки часто читают и пишут память без локального демона.
- Память проекта разделена по `project_id`, поэтому один проект может охватывать несколько репозиториев.

## Установка

Бинарь самодостаточный: в рантайме Go не нужен.

Homebrew (рекомендуется, Go не требуется):

```bash
brew install shilin23061991/tap/sentgraph-mcp
```

Через Go (нужен тулчейн Go 1.25+):

```bash
go install github.com/shilin23061991/sentgraph-mcp@latest
```

Проверка версии: `sentgraph-mcp version`.

## Установка в Claude Code

Бинарь ставится отдельно (brew или `go install` выше), всё остальное -- скилы, хуки и MCP -- одним плагином. Команды выполняйте из корня репозитория.

### 1. Ключи

Переменные окружения читаются первыми и всегда побеждают. Ключи, которых в окружении нет, `sentgraph-mcp` добирает из `.env.local` **в директории самого проекта** -- родительские каталоги не просматриваются, поэтому файл этажом выше не настроит соседние проекты. **Проект, где нет ни ключей в окружении, ни своего `.env.local`, не запустится** -- это защита от глобальной/случайной установки.

Вариант А -- файл в проекте (он в `.gitignore`, в коммит не попадёт; значения замените на свои):

```bash
cat > .env.local <<'EOF'
ZEP_API_KEY=вашключ
ZEP_USER_ID=вашид
SENTGRAPH_PROJECT_ID=имя-проекта
EOF
```

Вариант Б -- ключи из окружения, без файла. Работает, но с двумя оговорками, которые стоит знать заранее:

- **Блока `env` в `.mcp.json` мало.** Он достаётся только MCP-серверу; хуки Claude Code запускаются отдельными процессами в обычном окружении сессии и ключей оттуда не увидят. Настроившись только так, вы получите живые инструменты памяти и молча мёртвый автозахват. Чтобы окружение видели и хуки, ключи должен давать сам процесс сессии -- обёртка-менеджер секретов, запускающая агента, либо экспорт в профиле шелла.
- **Экспорт в профиле шелла снимает защиту от глобальной установки.** Проверка «проект настроен» смотрит на окружение процесса, а оно одинаково во всех каталогах: с экспортированными ключами любой каталог считается настроенным, и user-scope установка начнёт писать память везде. Хуже, если экспортирован `SENTGRAPH_PROJECT_ID`: он перебьёт значение из `.env.local` каждого проекта, и разные репозитории сольются в один граф.

Безопасный компромисс: `SENTGRAPH_PROJECT_ID` держать в `.env.local` проекта (он и определяет граф), а секреты подавать из менеджера на процесс.

### Миграция с версий до 0.5.0

Раньше `.env.local` искался вверх по дереву, поэтому один файл в общем каталоге (например, `~/code/.env.local`) настраивал все проекты под ним. Теперь так не работает. Проверьте каждый проект, где подключён sentgraph:

```bash
ls .env.local || echo "нужен свой .env.local"
sentgraph-mcp doctor          # молчит и отвечает config ok -- всё в порядке
```

Проектам, жившим на общем файле, скопируйте его в каждый: `cp ../.env.local .env.local`. Если общий `SENTGRAPH_PROJECT_ID` был одним на группу репозиториев -- сохраните то же значение, иначе единый граф расщепится на несколько. `serve` и `doctor` сообщат об отсутствии настройки сразу; хуки в ненастроенном проекте молчат, так что память там просто перестанет писаться без единого сообщения -- это и есть причина пройтись по списку руками.

- `ZEP_API_KEY` -- на дашборде проекта в разделе "API KEY"
- `ZEP_USER_ID` -- в разделе [Account](https://app.getzep.com/account/settings), Your Account ID
- `SENTGRAPH_PROJECT_ID` -- имя проекта из Zep

### 2. Установить плагин (скилы + хуки + MCP)

Команды `/plugin ...` вводятся внутри сессии Claude Code. Маркетплейс -- это сам GitHub-репозиторий; ставьте в скоуп проекта:

```text
/plugin marketplace add shilin23061991/sentgraph-mcp
/plugin install sentgraph@sentgraph-mcp --scope project
```

> `--scope project` обязателен: плагин (скилы + хуки + MCP) активен только в этом проекте. user scope (по умолчанию) поднял бы MCP-сервер и хуки во всех проектах.
>
> Подтверждение: project-сервер из соображений безопасности не стартует, пока вы его не одобрите. При первом запуске `claude` в проекте появится интерактивный запрос -- подтвердите его (один раз, руками; конфиги править не нужно). До этого `claude mcp list` показывает `Pending approval`; сбросить выбор -- `claude mcp reset-project-choices`.




### 3.CLAUDE.md проекта

Вставьте в **самый верх** `CLAUDE.md` вашего проекта (один раз):

```text
<sentgraph priority="critical">
ОБЯЗАТЕЛЬНО учитывай этот блок в каждой сессии и не игнорируй его. У тебя есть долговременная память через MCP-сервер `sentgraph` (Zep Cloud) -- активно ей пользуйся.

- В начале работы и при смене темы ОБЯЗАТЕЛЬНО вызывай `memory_context` и опирайся на полученный контекст.
- Нужен конкретный факт из прошлого -- вызывай `memory_search` с коротким точным запросом.
- Узнал устойчивое предпочтение, решение, факт проекта или важный урок -- сразу сохрани через `memory_add` (или скил `remember`), не жди конца сессии.
- Историей управляет пользователь: `session-history` -- посмотреть сохранённое, `forget` -- удалить.
- Рутинный захват беседы делают хуки. Не дублируй рутинные ходы; храни только то, что должно жить долго.
- НИКОГДА не сохраняй в память секреты, токены, API-ключи, учётные данные, приватные ключи.
</sentgraph>
```


### Проверка

```bash
sentgraph-mcp doctor --online   # конфигурация + связь с Zep (запускать из каталога проекта)
claude mcp list                 # sentgraph должен быть в списке
```
## MCP-инструменты

- `memory_context` -- собранный контекст пользователя и проекта.
- `memory_search` -- поиск по графовой памяти пользователя или проекта.
- `memory_history` -- недавние сообщения треда.
- `memory_add_messages` -- сохранить ходы беседы.
- `memory_add` -- сохранить факты или данные проекта/пользователя.
- `memory_forget` -- удалить edge, node или episode по UUID.

## Хуки

Конфигурация хуков плагина Claude -- в `plugin/hooks/hooks.json`.

События по умолчанию:

- `SessionStart` -- прочитать контекст и подгрузить его.
- `UserPromptSubmit` -- записать промт пользователя и подгрузить свежий контекст.
- `PreCompact` -- повторно подгрузить контекст перед компакцией.
- `Stop` -- сохранить последний ход ассистента из транскрипта.
- `SessionEnd` -- финальный проход сохранения.

## Релиз (мейнтейнерам)

Сборку и публикацию делает GoReleaser в GitHub Actions (`.github/workflows/release.yml`) по пушу тега `vX.Y.Z`. Он собирает бинари (darwin/linux × amd64/arm64), создаёт GitHub Release с архивами и обновляет cask в tap-репозитории [`shilin23061991/homebrew-tap`](https://github.com/shilin23061991/homebrew-tap).

Разовая настройка: в секретах репозитория задать `HOMEBREW_TAP_GITHUB_TOKEN` -- PAT с правом записи (`contents:write`) в `homebrew-tap` (дефолтный `GITHUB_TOKEN` не может пушить в другой репозиторий).

Выпуск версии:

```bash
git tag v0.5.0
git push origin v0.5.0
```
