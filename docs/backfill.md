# Перелив истории в память Zep

**Цель:** залить в память то, что случилось вне Claude Code — день с аудио-рекордера и
скринрекордера, архив разговоров, старые транскрипты, — одним прогоном, инкрементально и без дублей.

Инструмент: `scripts/backfill` (Go, использует уже подключённый `zep-go/v3` и `internal/redact`).

```bash
go run ./scripts/backfill -kind day -src ~/data/day/2026-08-09.jsonl -user <ZEP_USER_ID>
```

## Что на этот счёт говорит Zep

Batch API у Zep описан ровно как перелив: «load large historical datasets — backfills, migrations,
**archived conversations**». Это его кейс, а не индексация документации.

| Путь | Что это | Лимиты | Когда брать |
|---|---|---|---|
| `graph.add` | один эпизод за вызов | **10 000 символов** на эпизод (больше — 400, не обрезка); запросы в один граф идут **последовательно** | live-поток, то есть хуки sentgraph |
| **Batch API** (`client.Batch.*`) | draft → `add` → `process` → опрос; асинхронно, не мешает live-трафику | **350** items на `batch.add`, **50 000** на батч | **перелив истории — этот путь** |
| `zep-ingest` (Python, alpha 0.1) | готовые лоадеры Slack/`.eml`/VTT/CSV, preview, LLM-контекст | те же | если источник — Slack-экспорт или почта и лень писать парсер |
| `graph.AddBatch` | старый пакетный add | — | **не использовать: deprecated в пользу Batch API** |

Ещё из доки, что определило дизайн:

- **`created_at` на каждом элементе обязателен для истории.** Zep по нему строит `valid_at`/`invalid_at`
  фактов. Залил вчерашний разговор с сегодняшним временем — он «переспорит» то, что случилось позже.
- Дедупликации по содержимому нет: повторный прогон создаёт вторые эпизоды. Отсюда манифест.
- «Обработка завершена» и «поиск находит» — разные чекпойнты. Пустой поиск сразу после заливки — не повод
  перезаливать, получишь дубли.
- Метаданные эпизода: до 10 ключей, значения — скаляры или массивы скаляров.

**Проверено живьём 2026-08-09** на ключе из Proton Pass, оба режима назначения:

- `-graph`: `POST /api/v2/graph/create` → 201, `POST /api/v2/batches` → draft, `batch.add` → `process`
  → **succeeded 2/2** (≈50 с), `GET /batches/<id>/items` → `items[].episode_uuid`, поиск вернул факты
  с `valid_at`, равным времени события (не времени заливки), `DELETE /api/v2/graph/<id>` → 200.
- `-user`: `POST /api/v2/users` → 201, тот же цикл → **succeeded 2/2**, поиск по `user_id` находит,
  `DELETE /api/v2/users/<id>` → 200. Запуск на несуществующем пользователе честно падает до отправки.

Тестовые граф и пользователь снесены. Путь `-kind docs` проверен только dry-run.

## Формат дня (`-kind day`)

Вход — JSONL, одна строка на событие. Имена полей принимаются в синонимах, чтобы не писать конвертер
под каждый рекордер:

| Смысл | Принимаемые ключи |
|---|---|
| время (обязательно) | `ts`, `time`, `created_at`, `start` — RFC3339 или `2006-01-02 15:04:05` |
| текст (обязательно) | `text`, `content`, `transcript`, `ocr` |
| вид | `kind`, `source`, `type` — `audio` / `screen` / `note` |
| говорящий | `speaker`, `name` |
| приложение / окно | `app`, `application`, `title`, `window` |

```jsonl
{"ts":"2026-08-09T09:00:00Z","kind":"audio","speaker":"Стас","text":"Начинаем разбор бэклога."}
{"ts":"2026-08-09T10:30:00Z","source":"screen","app":"Chrome","title":"Zep Docs","ocr":"Batch ingestion limits"}
```

Как это становится эпизодами:

- События склеиваются, пока держится **сцена** (тот же вид + приложение + окно), разрыв во времени
  не больше `-gap` (по умолчанию 5 минут) и не набралось `-chunk` символов (по умолчанию 1200).
- Реплики с `speaker` уходят как `message` в формате `Имя: текст`; поток без говорящего
  (распознанный экран, заметки) — как `text`.
- Каждому эпизоду приписывается шапка `[дата 09:00–09:12 · audio · Chrome: Zep Docs]`,
  `created_at` = время первого события группы.
- **Весь текст проходит через `internal/redact`** до отправки — тот же фильтр секретов, что и у хуков.
  С экрана и из речи утекает больше всего; счётчик «redact: секреты вырезаны в N эпизодах» печатается.

Инкрементальность: манифест хранит `last_event_at` по каждому файлу. Дописал день — следующий прогон
возьмёт только события новее этой отметки. Файл, у которого ничего не прибавилось, пропускается целиком.

## Шаги

Ключ — из Proton Pass, в файлы не класть: `pass://Dev/ZEP_MY_AGGR_KEY/password`
(какой из двух ключей чей проект — **уточнить у Стаса**, оба отвечают 200 и оба проекта пустые).

```bash
# 0. Цель должна существовать. Для дня это обычно граф пользователя.
#    Путь именно /users (множественное число):
ZEP_KEY=pass://Dev/ZEP_MY_AGGR_KEY/password pass-cli run --no-masking -- sh -c '
  curl -s -X POST https://api.getzep.com/api/v2/users \
    -H "Authorization: Api-Key $ZEP_KEY" -H "Content-Type: application/json" \
    -d "{\"user_id\":\"<ZEP_USER_ID>\"}"'
# Для отдельного графа — POST /api/v2/graph/create (голый POST /graph — это добавление эпизода!)

# 1. Dry-run: сколько эпизодов, сколько символов, что именно поедет.
go run ./scripts/backfill -kind day -src ~/data/day/2026-08-09.jsonl -user <ZEP_USER_ID>

# 2. Прочитать превью глазами — это личные данные, там же видно работу redact.
open .ingest/day-preview.md

# 3. Отправка.
ZEP_API_KEY=pass://Dev/ZEP_MY_AGGR_KEY/password pass-cli run --no-masking -- \
  go run ./scripts/backfill -kind day -src ~/data/day/2026-08-09.jsonl -user <ZEP_USER_ID> -apply
```

Флаги: `-chunk` (символы, не байты), `-gap`, `-day-ext .jsonl,.ndjson`, `-graph` вместо `-user`,
`-manifest` (по умолчанию `.ingest/<kind>.json`), `-source` (метка в метаданных), `-timeout`.

**Куда лить.** День — в **граф пользователя** (`-user`): он подмешивается в контекст сессий через
`memory_context`. Отдельный граф (`-graph day:2026`) — если день не должен протекать в рабочий контекст
автоматически, а только по явному поиску.

## Документация (`-kind docs`) — вторым приоритетом

Тот же скрипт умеет каталог markdown: чанкинг по абзацам с цепочкой заголовков в шапке.
Но для доки проекта это сомнительный кейс: граф хранит извлечённые факты, а не текст для цитирования;
`docs/` и так лежит в репозитории; при обновлении доки версии начнут конфликтовать в темпоральном графе.
Оправдано только для знаний, которых у агента локально нет (вендорские контракты, приватные вики).

Замер: `docs/` этого репо, 3 файла, 32 629 символов → 72 эпизода при `-chunk 500`.

## Цена

- **Zep:** N эпизодов = сколько напечатал dry-run. День с плотным аудио и экраном легко даёт сотни.
- **Время:** заливка — минуты; обработка асинхронная, скрипт опрашивает до терминального статуса.
  Замер смоук-теста: 2 эпизода — около 50 секунд от `process` до `succeeded`.
- **LLM локально:** ноль, контекст к эпизодам приписывается сам.
- **Риск:** запросы в один граф Zep исполняет последовательно — большой перелив встанет впереди
  live-записей хуков. Гонять не посреди рабочей сессии.

## Проверка

```bash
# статус батча (batch_id есть в манифесте)
curl -s -H "Authorization: Api-Key $ZEP_KEY" https://api.getzep.com/api/v2/batches/<BATCH_ID>

# поиск (или MCP-инструмент memory_search)
curl -s -X POST https://api.getzep.com/api/v2/graph/search \
  -H "Authorization: Api-Key $ZEP_KEY" -H "Content-Type: application/json" \
  -d '{"user_id":"<ZEP_USER_ID>","query":"фраза из вчерашнего разговора","limit":5}'
```

Терминальные статусы: `succeeded`, `partial`, `failed`, `invalid`, `canceled`.
Разбор `partial`/`failed` — `GET /api/v2/batches/<BATCH_ID>/items`: у каждого элемента есть
`status`, `error`, `episode_uuid`.

## Откат

```bash
# UUID эпизодов батча
curl -s -H "Authorization: Api-Key $ZEP_KEY" \
  "https://api.getzep.com/api/v2/batches/<BATCH_ID>/items?limit=350" | jq -r '.items[].episode_uuid'

# удалить эпизод
curl -X DELETE -H "Authorization: Api-Key $ZEP_KEY" https://api.getzep.com/api/v2/graph/episodes/<UUID>
```

Если лил в отдельный граф — быстрее снести его целиком: `DELETE /api/v2/graph/<graph_id>`.
Незапущенный draft удаляется через `DELETE /api/v2/batches/<BATCH_ID>` (обработанный — уже нет).

Манифест `.ingest/day.json` — источник правды о принятом. При обрыве файл помечается `status: unknown`
без отметки прогресса, чтобы следующий прогон его разобрал, а не пропустил молча.

## Ловушки

- **Байты ≠ символы.** Лимиты Zep в символах; на кириллице байтовый счёт даёт вдвое мельче эпизоды,
  а обрезка по байтам рвёт UTF-8. В коде всё считается рунами — при правках не сломать.
- **Время события, а не время заливки.** Если рекордер не пишет таймкоды, перелив испортит временную
  шкалу фактов. Событие без времени скрипт отвергает, а не подставляет `now`.
- **Один манифест — одна цель.** Скрипт откажется работать, если цель графа не совпала с записанной.
- **Личные данные.** Превью и манифест пишутся с правами `0600` и лежат в `.ingest/` (в `.gitignore`).
  Аудио и экран — самый грязный источник: смотреть превью до `-apply`, а не после.
- **Batch без `process` ничего не делает** — draft висит и не тарифицируется.
- **Одна битая строка обрывает файл целиком.** JSONL разбирается строго: нераспознанный JSON или
  событие без времени останавливают прогон с указанием `файл:строка`. Это защита от молчаливой потери
  половины дня; чинить надо строку, а не игнорировать ошибку.
