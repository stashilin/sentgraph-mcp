# План: перенос sentgraph на TypeScript и раскатка памяти на всех агентов

Составлен 14.08.2026 по протоколу `bito-build-plan` (разведка через AI Architect —
8 запросов; внешний ресёрч — 6 агентов; замеры на этой машине). Уровень: Large.

## 1. Решение и рамки

**Новый закрытый репозиторий** на TypeScript; текущий Go-репозиторий остаётся
рабочим до приёмки и выводится из эксплуатации последним шагом.

Что решено (владельцем, по ходу планирования):

- Новый репозиторий называется **`zmem`**; так же называется и CLI — короткое имя
  вместо `sentgraph-mcp`, печатать его придётся часто.
- Распространение — **pnpm из git**, не Homebrew. Реестр npm не нужен вообще:
  `pnpm add -g git+ssh://git@github.com/stashilin/zmem.git#vX.Y.Z`.
  Проверено: SSH-доступ к GitHub работает, Claude Code клонирует маркетплейс
  плагина именно по SSH (`git@github.com:...` в remote кэша), поэтому закрытый
  репозиторий установку плагина не ломает.
- **Бинарь не в приоритете**, компиляция в standalone не делается.
- **Холодный старт не учитывается как фактор** (решение владельца, зафиксировано
  явно). Замеры сохранены в §7 как контекст, а не как аргумент.
- Форма: **библиотека + тонкие CLI** (вариант «Б»). Ядро публикуется как
  импортируемый модуль; CLI, плагины и будущие прод-агенты — его потребители.

Что умирает вместе с Homebrew: tap `stashilin/homebrew-tap`, cask, GoReleaser,
секрет `HOMEBREW_TAP_GITHUB_TOKEN`, вся возня с подписью macOS.

## 2. Целевая архитектура

```
zmem — закрытый репозиторий, pnpm-монорепо
│
├── packages/core        @zmem/core — вся логика, единственная копия
│   ├── config           env-first + .env.local в директории проекта
│   ├── redact           вырезание секретов ДО любой отправки
│   ├── memory           Service: лимиты, чанки, роутинг user/project
│   └── zepstore         адаптер @getzep/zep-cloud за интерфейсом Gateway
│
├── packages/cli         zmem — serve | hook | doctor | ingest
│
├── packages/amp-plugin  agent.start / agent.end, импортирует core напрямую
│
└── plugin/              плагин Claude Code (hooks.json + скилы), маркетплейс
```

Ключевое отличие от нынешней схемы: **плагины Amp и omp импортируют ядро как
модуль**, а не запускают процесс. Отдельный вход `ingest` нужен только Codex —
у него хуки это внешние процессы.

```
WS0 (страховка)
  └─▶ WS1 (каркас) ─▶ WS2 (ядро) ─┬─▶ WS3 (CLI) ─▶ WS4.1 Codex ─┐

                                       WS4.3 плагин CC ─────────┘
```

WS0 — единственный жёсткий барьер: без золотых векторов остальное стартовать
нельзя. Внутри WS2 задачи 2.1–2.2 идут до 2.4–2.5. Adapters (4.1–4.3)
параллельны друг другу.

**Альтернативный порядок, если память нужна у остальных агентов раньше:**
сделать `ingest` и Codex-адаптер в текущем Go-репозитории (2–3 дня), а порт
начать после. Цена: `ingest` придётся написать дважды.

## 5. Сквозные вопросы

**Паритет, а не «переписал и ладно».** До удаления Go-кода обе реализации
прогоняются на одном входе: золотые векторы redact и обрезки, плюс сравнение
выхода `hook SessionStart` и `tools/list` байт в байт.

**Приёмка — измеренная память, а не конфиг.** Для каждого агента: записал ход →
нашёл его поиском в том же графе. Урок 13.08: sentgraph месяц выглядел
установленным в пяти проектах и не писал ни байта.

**Откат.** Go-репозиторий и рабочая установка v0.5.0 остаются нетронутыми до
конца WS5; откат — переустановка плагина из старого маркетплейса и `brew
install --cask`.

**Секреты.** `.env.local` в каждом проекте (уже созданы). Учесть: рантайм сам
подхватывает `.env`/`.env.local` из cwd — гейт `RequireProjectConfig` обязан
читать файл сам, а не полагаться на автозагрузку, иначе чужой `.env` молча
настроит посторонний каталог.

**Наблюдаемость.** `doctor` остаётся единственной командой проверки; в него
добавить, откуда пришла конфигурация (env или файл) — сейчас этого не видно, а
после смены контракта это первый вопрос при разборе.

## 6. Риски

| Риск | Вероятность | Влияние | Митигация | Ранний признак |
|---|---|---|---|---|
| `String.replace` без `/g` заменит только первый секрет → утечка в Zep | Высокая | **Критическое** | WS0.1 + золотые векторы; ревью каждого паттерна | Тест «два секрета одного вида» падает |
| Обрезка по `length` (UTF-16) вместо кодовых точек → расхождение лимитов на кириллице | Высокая | Среднее | WS2.2 + векторы границ | Длина в тесте не совпадает с Go |
| Пустая строка вместо `nil` уедет в Zep (`name`, `createdAt`, `sourceDescription`) | Средняя | Среднее | `|| undefined` в трёх местах, тест на сериализацию | Поле появилось в запросе |
| TS MCP SDK не добивает `content[]` из `structuredContent` | Высокая | Высокое | Возвращать оба поля в каждом хендлере | Claude Code видит пустой ответ |
| Инлайн-флаги `(?i)`/`(?s)` из Go не компилируются в JS | Высокая | Низкое (шумно падает) | Флаги конструктора при переносе | SyntaxError на старте |
| Бэктрекинг JS-регулярок (в Go RE2 его нет) на длинных текстах бэкфилла | Средняя | Среднее | Тест на 20k символов без пунктуации | Время чанкинга растёт нелинейно |
| Дубли эпизодов из-за ретраев SDK на write-путях | Средняя | Среднее | `maxRetries: 0` на записи, манифест `last_event_at` | Повторы в графе после сбоя сети |

## 7. Замеры: не фактор решения, но три инженерных следствия

Владелец вывел скорость старта из факторов — раздел оставлен ради решений
по реализации, а не как аргумент за или против переноса.

Измерено на этой машине (n=50 на вариант, пол fork/exec 1.99 мс): нынешний
Go-хук 3.81 мс; сборка «pnpm-шим → mise → node → статический SDK» — 54.99 мс.
При таймауте хука 20 секунд это доли процента бюджета, но три вещи стоит
заложить в реализацию сразу, потому что потом их дороже переделывать:

1. **Ленивый импорт Zep SDK.** Если импорт не выполняется, он стоит +0.96 мс;
   если выполняется — +44 мс. Путь «проект не настроен» и путь чтения
   контекста не должны трогать SDK вовсе. Задача 3.2 принимает это как
   требование.
2. **Собирать CLI бандлом** (esbuild или аналог): 448 CJS-модулей SDK против
   одного файла — 69.7 мс против 35.9 мс. Но бандл ухудшает *ленивый* путь на
   4.2 мс, поэтому либо бандлить с сохранением динамического импорта, либо
   осознанно выбрать одно из двух.
3. **Никакого `npx` в хуках.** Он стоит 491–512 мс на вызов даже с точным
   пином версии (пин не отменяет похода в реестр). Известный прецедент —
   ruflo#1530, где это дало 18–21 секунду на промпт. Установка только через
   `pnpm add -g`, вызов — по имени команды.

Побочный факт на будущее: если бы понадобилось оставить ядро на Go и всё равно
раздавать через pnpm, это рабочий путь — паттерн `optionalDependencies` с
платформенными пакетами (как у turbo и biome, без postinstall-скачивания);
кросс-собранные Go-бинари подписываются линкером ad-hoc и не карантинятся.
Цена — 11–15 мс из-за обязательного шима.

## 8. Открытые вопросы

| # | Вопрос | Что блокирует | Кто решает |
|---|---|---|---|
| 1 | Порядок: полный порт или сначала `ingest`+Codex на Go | Старт WS3.4/WS4.1 | владелец |
| 2 | Судьба `scripts/backfill` — переносить или оставить в архиве Go | Объём WS2 | владелец |
| 3 | omp-адаптер делает владелец; нужен ли ему `ingest` или импорт ядра | Форма публичного API ядра | владелец |

Имя решено: репозиторий и CLI — `zmem`. Переименование команды затрагивает
`hooks.json` плагина, `.mcp.json`, записи в `~/.codex/hooks.json` и все шесть
проектов; это часть WS5.1, отдельной задачи не требует, но при раскатке старые
и новые записи не должны сосуществовать — иначе память будет писаться дважды.

## 9. Context Handoff (for downstream skills)

- **Репозиторий (источник):** `stashilin/sentgraph-mcp`, проиндексирован в AI
  Architect 14.08.2026, состояние In-Sync.
- **Ближайший аналог для порта:** сам Go-код; карта файлов и размеров —
  `getFieldPath(sentgraph-mcp, file_structures)`.
- **Инварианты Zep (подтверждены доменным знанием):** лимиты в символах, не
  байтах — 30 сообщений/вызов, 4096 симв/сообщение, 10000 симв/эпизод, 350
  items/`batch.add`, 50000/batch; метаданные ≤ 10 ключей; `created_at`
  определяет временную валидность фактов.
- **Инвариант проекта:** `redact` применяется до любой отправки; граф проекта —
  `proj:` + `SENTGRAPH_PROJECT_ID`, один проект может охватывать несколько
  репозиториев.
- **Соглашения:** документация и коммиты на русском, идентификаторы на
  английском; конвенции стека берутся из paynexus (Zod, Vitest, Biome, mise).
- **Отложено (не в объёме):** прод-агенты paynexus подключат то же ядро, но
  это отдельная работа; omp-адаптер за владельцем.
